Project

Panel-vendor API consumer

Bain & Company (NPS Prism) · 2023

← Projects

Situation. At NPS Prism, client survey data came from two panel vendors, Dynata and Qualtrics. Each had a portal with dashboards and a manual download. Two Insights Engineers, among other duties, logged in, downloaded the Excel files and consolidated them by hand, loading them in micro-batches. The process had no audit trail and no data governance.

Task. Replace the manual download with an automatic, auditable ingestion that worked the same way for both vendors: take a repetitive task away from two people and create a data process that did not exist yet.

Action. What I proposed, what a colleague built, and what I changed:

  • I noticed both vendors already exposed APIs and proposed an API consumer, running as a scheduled Databricks job and landing the data in the raw layer.
  • A colleague wrote the first version: one endpoint, procedural style, no pagination, filters, field projection or sorting.
  • I evolved it to object-oriented code with a common interface and one concrete class per vendor (DynataProvider, QualtricsProvider). Adding a vendor now means adding one class.
  • In Python, I implemented cache decorators to stay within the APIs' rate limits, plus pagination, filters, projection and sorting.
  • I defined the layered architecture. Bronze uses Delta Lake on Parquet, which gives schema evolution against schema drift and compressed data, replacing the JSON the team used. Silver would be a data-warehouse model, which I designed but did not implement.

Architecture. In the diagram above, Databricks Workflows triggers the consumer on a quarterly schedule. Each provider class talks to its vendor's API: Dynata with signed requests (access key, secret and expiry), Qualtrics with an asynchronous export (start, poll progress, fetch the file). Shared decorators handle cache, retry and rate limits, and everything lands in bronze. Qualtrics in particular allows about 350 requests an hour with OAuth and fails exports above 1.8 GB, so extractions are filtered by date window.

Result. Measured on the quarterly batch:

  • Volume: about 60 thousand forms per client, with 50 to 120 responses each, that is 3 to 7.2 million responses per client per quarter. For at least 10 clients, 30 to 72 million responses per quarter, processed in batch.
  • End of manual work: two people stopped downloading and consolidating files by hand. Each download was short, about 10 minutes; the real gain was removing a repetitive, error-prone task from people.
  • Processing cost: a few hundred dollars a month saved once the Excel micro-batches were gone.
  • Audit and governance: the pipelines and the data layers were created from scratch. Every load became traceable and reproducible.
  • Room to grow: Delta and Parquet with schema evolution, and a common interface for new vendors.

Tech: Python (OOP, decorators), Databricks Workflows, Delta Lake, Parquet, Dynata and Qualtrics REST APIs
